# Jinx — Prismaxys Bot

Основа Telegram-бота: регистрация пользователей в SQLite, проверка членства в канале,
личное меню, тарифы и помощь. Работает в личных сообщениях через polling.
Цена, срок, устройства и статус VPN пока отображаются как «—».
Продажи, выдача VPN-доступа и платные подписки ещё не реализованы.

## Локальная настройка

Нужны Python 3.12 или 3.13 и [uv](https://docs.astral.sh/uv/getting-started/installation/).
В корне репозитория выполните:

```bash
uv sync --frozen
cp .env.example .env
uv run --frozen jinx-bot --check
```

`--check` проверяет настройки и создаёт базу без токена и запросов к Telegram.
По умолчанию база находится в `data/jinx.sqlite3`; сохраняйте этот файл между
перезапусками. Для резервной копии работающей базы используйте SQLite backup API:
копирование одного файла во время работы не учитывает незаписанные данные WAL.

## Подключение Telegram

1. Создайте бота через [@BotFather](https://t.me/BotFather) и задайте его токен
   в `JINX_BOT_TOKEN` локального `.env`.
2. Добавьте бота администратором канала `-1002819525144`, чтобы проверять членство
   пользователей. Для другого канала измените `JINX_CHANNEL_ID`.
3. Укажите реальную HTTPS-ссылку вступления в `JINX_CHANNEL_URL`, когда она будет
   доступна. Без ссылки бот предлагает повторить проверку, но не показывает кнопку вступления.
4. Запустите один процесс для этого токена:

```bash
uv run --frozen jinx-bot
```

Бот перед запуском проверяет токен, отсутствие активного webhook и свои права
администратора канала. При существующем webhook запуск останавливается: бот не удаляет
его автоматически. Если бот уже обслуживается другим приложением, сначала согласуйте
переключение и отключите прежний процесс или webhook.

После запуска отправьте боту `/start` в личном чате. Проверьте вступление и повторную
проверку членства, личный кабинет, тарифы и `/help`. Помощь доступна без членства;
сбой проверки Telegram не открывает доступ к личному меню.
Без токена и прав администратора живой бот не запущен и не проверен.

Проверка `Server connectivity` в Actions подтверждает доступность SSH с GitHub
до обоих серверов, без входа по паролю. Развёртывание ещё не настроено; для него
понадобится отдельный workflow и защищённые credentials в GitHub Secrets.

## Настройки

Настройки читаются из переменных окружения `JINX_*` и локального `.env`.
Переменные окружения имеют приоритет.

| Переменная | Значение |
| --- | --- |
| `JINX_BOT_TOKEN` | Секретный токен; обязателен для polling, не нужен для `--check` |
| `JINX_CHANNEL_ID` | ID канала; по умолчанию `-1002819525144` |
| `JINX_CHANNEL_URL` | Необязательная HTTPS-ссылка вступления в Telegram-канал |
| `JINX_MINI_APP_URL` | Необязательная HTTPS-ссылка опубликованного Mini App; включает кнопку |
| `JINX_SUPPORT_URL` | Необязательная HTTPS-ссылка поддержки |
| `JINX_DATABASE_PATH` | Путь SQLite; по умолчанию `data/jinx.sqlite3` |

Оставляйте необязательные ссылки и токен пустыми, пока их нет. `.env` и база
исключены из Git. Не публикуйте токен, содержимое базы или серверные секреты.
Настройка ссылки Mini App сама по себе не создаёт приложение.

## Проверки

```bash
uv run --frozen pytest
uv run --frozen ruff check .
uv run --frozen ruff format --check .
uv build
```

Тесты используют временные базы SQLite и подмену внешнего Telegram API;
реальный токен и отправка сообщений не нужны. GitHub Actions повторяет эти проверки
на Python 3.12 с зафиксированными зависимостями.
