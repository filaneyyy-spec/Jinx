# Основа Telegram-бота Prismaxys

Пользователь поручил сначала реализовать основу бота, затем сообщить следующий шаг. Тарифы пока отображаются прочерками. Позже будут Stars, ЮKassa на отдельном сайте, Mini App, VPN-подписки и Windows-клиент; Android отложен.

Текущий результат: запускаемый Python 3.12+ бот на aiogram, который работает в личных сообщениях, сохраняет пользователя в SQLite и проверяет членство в канале `-1002819525144`. Меню: моя подписка, тарифы, помощь. `/start` и `/help` доступны; личный кабинет и тарифы проверяют актуальное членство. Если ссылка на канал ещё не настроена, бот не выдумывает её, но позволяет повторить проверку.

Неучастнику показывается предложение вступить и кнопка проверки. Участники, администраторы и владелец проходят; restricted проходит только с is_member=true. Ошибка Telegram не считается отсутствием подписки и не открывает доступ. Данные берутся из отправителя обновления, а не из callback payload. Бот не выводит технические ошибки или токены пользователю.

Тарифы, цена, срок, устройства и статус VPN пока показываются как «—» с объяснением, что продажи и выдача доступа ещё не подключены. Кнопок реальной оплаты и несуществующих ссылок подключения нет. Кнопка Mini App появляется только при явно настроенном HTTPS URL. Помощь доступна независимо от членства.

SQLite содержит одну запись на Telegram user ID и сохраняется между запусками. Повторный /start обновляет имя, не создаёт дубликат. Группы не обрабатываются как личный кабинет. Конфигурация через JINX_* переменные и локальный .env, исключённый из Git. Токен отсутствует по умолчанию; CLI сообщает об этом без трассировки или секретов. Проверка конфигурации и базы работает без токена и без Telegram.

Запуск через polling только после проверки личности бота, отсутствия активного webhook и прав администратора в канале. Не удалять существующий webhook автоматически и не пропускать накопленные обновления. Один процесс polling на токен. Корректно закрывать HTTP-сессию и базу. Сбой проверки Telegram объяснять без утечки секрета.

Проверка: реальные SQLite-тесты, обработка синтетических Telegram Updates через настоящий Dispatcher с подменой только внешнего Telegram API, проверки ошибок и членства, CLI, lint и сборка пакета. GitHub Actions повторяет проверки с frozen lockfile. Живой запуск требует реального токена и административных прав бота в канале.
